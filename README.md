# fconline-mcp

넥슨 Open API의 **FC 온라인** 경기 데이터를 MCP(Model Context Protocol) 도구로 제공하는 서버입니다.
Claude Code 같은 AI 어시스턴트에 연결하면 "요즘 폼 어때?", "내 델피에로 랭커랑 비교해줘" 같은 질문에
AI가 필요한 도구를 직접 골라 실제 경기 기록을 조회하고 분석합니다.

```
나: "최근 감독모드 10판 어땠어?"
 └ Claude Code ── summarize_form 호출 ──▶ fconline-mcp ── HTTP ──▶ 넥슨 Open API
                ◀── 전적·득실점·슈팅 효율·자주 쓴 선수 요약 ──┘
```

## 만든 이유

전적 사이트는 개발자가 미리 정해 둔 통계 화면만 보여 줍니다. 알고 싶은 건 그때그때 다릅니다.
"점유율이 높았는데 진 경기", "이 선수 슈팅이 랭커보다 적은지"처럼요.
그래서 데이터 조회는 도구로 만들어 두고, 질문에 맞게 어떤 도구를 어떤 순서로 부를지는 AI가 정하게 했습니다.

## 도구

| 도구 | 하는 일 |
|---|---|
| `find_user` | 닉네임 → 레벨, 매치 종류별 역대 최고 등급 |
| `get_recent_matches` | 최근 경기 목록 (날짜, 승패, 스코어, 상대, 점유율) |
| `get_match_detail` | 경기 하나의 요약 (양 팀 지표, 득점 기록, 내 선발 라인업과 평점) |
| `summarize_form` | 최근 n경기 집계 (전적, 득실점, 슈팅 효율, 패스성공률, 자주 쓴 선수) |
| `get_player_stats` | 특정 선수의 경기당 세부 기록 (슈팅·패스·드리블·공중볼·태클 등과 성공률) |
| `compare_with_rankers` | 내가 쓴 선수 기록 vs 같은 카드·포지션 랭커 평균 |
| `get_position_trends` | 최근 상대들이 특정 포지션에 실제로 쓴 선수 (추천 후보 수집) |
| `get_ranker_stats` | 선수·포지션별 랭커 기록 (다른 선수 추천의 근거) |

## 설계에서 정한 것

**1. 응답은 작게, 세부 기록은 따로.**
경기 상세 원본은 한 경기에 약 17KB입니다. 그대로 넘기면 10경기만 봐도 AI의 컨텍스트가 금방 찹니다.
`get_match_detail`은 판단에 필요한 팀 지표, 득점, 선수 평점만 돌려줍니다.
선수별 세부 기록은 `get_player_stats`를 따로 불렀을 때만 꺼냅니다.

**2. 도구 설명(docstring)이 곧 사용 설명서.**
AI는 코드를 보지 않고 도구 설명만 읽고 도구를 고릅니다. 그래서 설명에 "언제 이 도구를 쓰고, 언제 다른 도구를 쓰는지"를 적었습니다.
예를 들어 `summarize_form`에는 "여러 경기를 묶어 보는 질문에는 get_match_detail을 여러 번 부르지 말고 이 도구를 먼저 쓴다"고 적어,
경기 상세를 10번 호출하는 낭비를 막았습니다.

**3. 없는 데이터는 지어내지 않게.**
넥슨 Open API에는 선수 능력치(속력, 슛 등)가 없습니다. 선수 목록에는 ID와 이름만 들어 있습니다.
그래서 선수 추천은 능력치가 아니라 **랭커들이 그 카드로 실제로 낸 기록**을 근거로 합니다.
선수 이름은 넥슨 선수 목록에서 확인하고, 없으면 비슷한 이름을 돌려줍니다.
AI가 없는 선수를 추천하지 못하게 하려는 장치입니다.
랭커 표본이 10경기 미만이면 신뢰도가 낮다는 경고를 붙입니다.

처음에는 "LW에 쓸 만한 선수 추천해줘"에 답할 도구가 없어서, AI가 후보 이름을 스스로 떠올려야 했습니다.
넥슨 API에는 "랭커가 이 포지션에 많이 쓰는 선수" 목록이 없습니다.
그래서 `get_position_trends`로 **내 최근 경기 상대들이 그 포지션에 실제로 쓴 선수**를 모으고,
그 후보를 `get_ranker_stats`로 검증하게 했습니다. 후보 수집부터 근거 확인까지 전부 실제 데이터로 이어집니다.

**4. API 문서와 실제 동작 확인.**
- `seasonid` 메타데이터는 2026-11-19 종료 공지가 있어서 처음부터 `class` 메타데이터를 썼습니다.
- `ouid`는 바뀔 수 있다고 문서에 적혀 있어서 10분만 캐시합니다.
- 받아 둔 데이터는 30일 안에 갱신해야 한다는 약관이 있어서 메타데이터 캐시는 7일로 잡았습니다.
- 랭커 스탯은 한 번에 20개까지는 되고 40개는 오류가 났습니다. 그래서 20개씩 나눠 호출합니다.
- 랭커 집계 대상이 아닌 카드가 하나만 섞여도 묶음 전체가 400 오류가 납니다. 이때는 하나씩 다시 불러 그 카드만 건너뜁니다.
- 개발 단계 키는 호출 제한이 빡빡합니다. 동시 4개 호출에서 429 오류가 자주 나서 동시 2개로 줄이고 재시도를 넣었습니다.

## 실제 데이터로 검증하며 찾은 것

도구를 실제 계정(감독모드)에 돌려 보고, 결과를 직접 계산한 값과 대조했습니다.

**1. 넥슨 원본 팀 평점은 화면의 평균평점과 정의가 다르다.**
경기 상세의 팀 평균평점이 3.29, 3.94처럼 이상하게 낮았습니다. 선발 11명의 평점을 직접 평균 내면 5.39, 6.45입니다.
계산해 보니 넥슨 `matchDetail.averageRating`은 **선발 11명 평점의 합을 교체 포함 18명으로 나눈 값**이었습니다
(59.3 ÷ 18 = 3.29, 70.9 ÷ 18 = 3.94로 두 경기 모두 정확히 일치).
지금은 원본 값을 쓰지 않고 선발 평점으로 직접 계산하며, 항목 이름도 `선발 평균평점`으로 바꿨습니다.

**2. 랭커 표본은 카드당 20경기에서 잘린다.**
감독모드와 공식경기 모두 모든 카드의 랭커 표본이 정확히 20경기였습니다.
그래서 "20경기"는 많이 쓰인다는 뜻일 뿐 순위 근거가 아니라고 도구 설명에 적었습니다.

**3. 이 등급대 상대들은 LW 자리가 없는 포메이션을 쓴다.**
`get_position_trends`를 처음 돌렸을 때 감독모드 20경기에서 상대의 LW 선발은 0명, ST도 0명이었습니다.
대부분 LAM·CAM·RAM과 LM·RM을 썼습니다.
그래서 비슷한 역할의 포지션을 묶어 세고(LW → LW·LF·LM·LAM), 결과마다 실제 포지션을 표시합니다.
묶은 뒤에도 후보 20명이 모두 1회씩만 쓰여서 순위는 의미가 없었습니다.
이럴 때는 도구가 스스로 "후보 목록으로만 보라"는 경고를 붙입니다.

**4. 교체 투입 선수의 기록은 확인되지 않았다.**
22경기 원본에서 교체 명단(SUB) 308건 모두 기록이 비어 있었습니다.
교체가 없었는지, 넥슨이 교체 선수 기록을 남기지 않는지는 아직 가리지 못했습니다.
평점과 집계는 선발만 쓰므로 결과에는 영향이 없습니다.

**5. 데이터끼리 서로 맞는지 대조**
게임 안에서는 지난 경기의 상세 기록을 다시 볼 수 없어서, 화면과 대조하는 대신
같은 경기 안의 서로 다른 필드가 맞는지를 확인했습니다. 감독모드 최근 20경기, 양 팀 모두 확인한 결과입니다.

| 확인 항목 | 결과 |
|---|---|
| 스코어 = 득점 기록(shootDetail) 건수 | 20/20 |
| 스코어 = 선수별 골 합계 | 20/20 |
| 도움이 붙은 득점 수 = 선수별 도움 합계 | 20/20 |
| 승/무/패 = 스코어 | 20/20 |
| 슈팅 ≥ 유효슈팅 ≥ 골 | 20/20 |
| 양 팀 점유율 합 = 100 | 20/20 |

같은 방식으로 직접 계산해 대조했기 때문에 1번의 평점 정의 차이를 찾을 수 있었습니다.

**6. AI의 도구 선택**
| 질문 | AI가 고른 도구 |
|---|---|
| "감독모드 최근 10판 어땠어?" | `summarize_form` 1회 (경기 상세를 여러 번 부르지 않음) |
| "최근 경기 하나 자세히" | `get_recent_matches` → `get_match_detail` |
| "내 델피에로 랭커랑 비교해줘" | `compare_with_rankers` 1회 (랭커 표본 5경기 경고 표시) |
| "LW에 쓸 만한 선수 추천해줘" | 처음엔 맞는 도구가 없었음 → `get_position_trends` 추가 |

**7. 오타를 넣으면 원하는 선수가 후보 4번째였다.**
"손홍민 랭커 기록 보여줘"를 넣자 후보가 홍진민, 홍성민, 송홍민, 손흥민 순으로 나왔습니다.
AI가 1순위를 고르면 엉뚱한 선수 기록을 보여 줄 수 있습니다.
원인은 글자 단위 비교였습니다. '흥'과 '홍'은 서로 다른 글자라 완전히 틀린 것으로 셉니다.
한글을 자모로 풀어(흥 → ㅎㅡㅇ, 홍 → ㅎㅗㅇ) 비교하고, 점수가 같으면 카드가 많은 선수를 앞에 두도록 바꿨습니다.
'살라', '케인'처럼 한 단어만 넣으면 '모하메드 살라', '해리 케인'이 후보에 아예 없었던 문제도 같이 고쳤습니다.
지금은 손흥민, 모하메드 살라, 해리 케인이 각각 1순위로 나옵니다.

## 한계

- **팀 전체를 랭커와 비교하려면 선수마다 한 번씩 호출해야 합니다.** "내 팀에서 랭커보다 못하는 선수 있어?"를 물으면
  AI가 `compare_with_rankers`를 선발 11명에게 하나씩, 11번 부릅니다. 실제로 11번 모두 오류 없이 끝났습니다.
  넥슨 랭커 API는 한 번에 20명까지 받으므로 팀 단위 도구를 만들면 1번 요청으로 줄일 수 있지만, 지금은 만들지 않았습니다.
- **추천 후보 표본이 작습니다.** `get_position_trends`는 내 최근 20경기(기본값, 최대 30) 상대만 보므로, 포지션당 후보가 20~30명 안팎입니다.
- **교체 투입 선수 기록은 확인하지 못했습니다** (위 4번).

## 설치와 연결

필요한 것: Python 3.12+, [uv](https://docs.astral.sh/uv/), 넥슨 Open API 키 ([openapi.nexon.com](https://openapi.nexon.com)에서 FC 온라인 앱 등록)

```bash
git clone https://github.com/marahohc/fconline-mcp.git
cd fconline-mcp
cp .env.example .env      # .env 파일에 NEXON_API_KEY 입력
uv sync
```

**Claude Code**: 이 폴더에서 `claude`를 실행하면 `.mcp.json`의 `fconline` 서버를 쓸지 묻습니다. 승인하면 바로 쓸 수 있습니다.
다른 폴더에서도 쓰려면:

```bash
claude mcp add fconline -- uv run --directory /path/to/fconline-mcp fconline-mcp
```

## 테스트

```bash
uv run pytest
```

요약 로직(득점 시간 변환, 교체 선수 제외, 선발 평균평점, 전적·득실점 집계, 랭커 비교 경고, 상대 포지션 집계, 선수 이름 후보 순서)을 가짜 데이터로 검증합니다.
실제 API는 호출하지 않습니다.

## 개발 방식

코드는 Claude Code로 작성했습니다.
도구 구성, 응답에 남길 항목, 추천 근거를 능력치 대신 랭커 기록으로 정한 것 같은 설계는 직접 정했습니다.
